# 游戏盘挂载失败修复

入口：SteamOS → 双系统用户专用 → 下一页：更多双系统工具 → 修复游戏盘挂载失败。

适用于 NTFS 游戏盘在文件管理器中报 `wrong fs type, bad option, bad superblock`，但系统自动挂载方式无法打开的情况。此错误本身不能证明文件系统损坏。

流程：列出未挂载的 NTFS 分区与容量、卷标，用户输入完整设备名确认；按需安装 NTFS-3G 驱动与修复工具；先以只读、禁止自动恢复的方式检查实际目录，包含 Windows 目录则拒绝修改；卸载检查挂载后运行 `ntfsfix`，成功后明确使用 `mount -t ntfs-3g` 挂载，并核对实际挂载点和可写状态。家目录的“互通盘”链接指向最终目录。安装组件期间保留并恢复原有系统只读状态，保留包签名检查，不刷新仓库或整机升级。

2026 年新版软件包将 `ntfsfix` 拆到 `ntfsprogs`；仅安装 `ntfs-3g` 可能仍提示找不到修复命令。兼容旧仓库中未拆包的安装方式，并在安装后核对实际命令。

本功能修改文件系统元数据，需要管理员权限，重要数据应先备份。不处理已挂载的盘、不格式化、不修改 fstab 或自动挂载策略、不删除 Windows 休眠文件、不清除坏簇记录。无法只读识别、分区状态变化、修复失败或只读挂载均不会报告修复完成。无法安全检查或需要完整 NTFS 修复时，进入 Windows 对正确盘符运行 `chkdsk /f`，然后完整关机。

挂载目录根据当前用户和分区 UUID 生成，不硬编码设备或卷标；挂载为当前会话有效，重启后若自动挂载仍失败，可再次使用此入口。原有 Steam 游戏库路径不会自动迁移，必要时在 Steam 中重新选择实际目录。

验证：本次用户已在 SteamOS 上确认安装 `ntfsprogs`、执行 `ntfsfix` 后，显式使用 NTFS-3G 挂载成功。工具箱集成仅在 macOS 做静态与完全模拟测试；安装、Windows 分区拒绝、只读挂载、修复失败与保护恢复均有模拟覆盖，尚需完整菜单流程的 SteamOS 实机验证。
