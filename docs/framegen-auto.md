# 小黄鸭 2.0 与 FSR4 自动中文包

任务：`.github/workflows/sync-framegen-zh.yml`。每天 UTC 01:17 启动轻量间隔判断，仅在 Unix 日期序号为偶数时查询上游，所以跨月仍是每 48 小时检查一次；手动触发和流程代码更新会立即检查。运行在 GitHub Actions，不依赖维护电脑开机。

## 发布顺序

1. 查询两个指定上游的最新正式 Release，只接受唯一预期 ZIP、官方固定下载路径及 GitHub 返回的 SHA256。不采用预发布版，不降低版本。
2. 版本、上游包 SHA256 与自动汉化规则修订号均没有变化时跳过。修复汉化规则后递增 `TRANSLATION_REVISION`，允许重打相同上游版本的旧自动包；不会改动历史资产。
3. 完整中文已内置在上游时保留官方包和署名；否则优先使用 `data/framegen_zh.json` 中的现有措辞。新增界面文案使用固定版本的离线翻译模型生成中文，检查数字、占位符和软件名称。
4. Acorn 只解析前端，按作用域追踪界面文案，覆盖单词、子页面、通知、辅助函数、动态片段与列表显示名；界面表达式添加文字转换及黄色汉化署名。去掉这些包装后，语法树必须和原始前端一致；不执行上游 JavaScript、后端或运行组件。样式与脚本元素的内容不翻译。
5. 保留后端、运行组件、许可证与作者。Decky 把列表名与后端注册名称绑定，小黄鸭 2.0 的 `plugin.json.name` 与前端两种协议的 `connect()` 注册名称须同步为 `小黄鸭2.0`，对应本地图片 URL 也同步映射；原方法、参数、事件和功能代码保持不变。禁止只改清单或只改连接一端。检查所有上游捆绑运行组件的 SHA256，输出完整包、全部文件校验表、权限信息与 `RENKIT_UI_COVERAGE.json` 文案核对清单；没有中文的界面文字或名称校验失败时，构建和上传均必须停止。
6. 上传到现有 Gitee 镜像仓库的新版本目录。从公开地址下载并重组整个文件，SHA256 一致后最后发布 `framegen-auto/catalog.json`。失败不修改下载版本信息，不 force push，不删除旧发布来绕过配额。

汉化修订5额外追踪 React 异步状态、后端返回的状态/错误/文件标签和动态提示模板；含 `ENABLE_GAMESCOPE_WSI=0` 等命令的说明仍按界面文案检查。只在显示时翻译已核对的固定片段，游戏名、路径、动态参数、文件内容与后端字节不变。同版本比较汉化修订号，客户端以随包携带的已核对清单为下限，避免旧缓存或备用安装退回部分中文包。

小黄鸭 2.0 使用 mirror-4 的 `lsfg-v2-zh-auto`；FSR4 使用 mirror-3 的 `fsr4-zh-auto`。初始清单可引用现有已校验的 `*-zh-signed` 资产。此流程不更新或引用独立中文发布仓库。

## 凭据与检查

- 沿用仓库已有的 `GITEE_TOKEN` secret。发布步骤才会接收这个 Token，通过临时 Git askpass 读取，不把 Token 写进远程 URL 或提交文件。
- `GITHUB_TOKEN` 仅用于读取上游正式 Release 元数据。
- 翻译无需付费 API Key。模型版本和依赖版本固定在脚本及工作流中，更新流程时会在云端测试新文案翻译。
- 模型失效、文案检查不通过、前端结构改变或上传失败时，任务失败并保留上一可用包。补齐词典或修复规则后手动运行任务即可重试尚未发布的新版本。

## 客户端

Renkit 读取并验证清单，保留已缓存的较新版本。SteamOS 的常用组合与新机初始化先选择旧版或 2.0；初始化把选择传给组合，避免重复询问。选择 2.0 后，下载并检查完整包，再停止商城，把旧 1.0、2.0 和可识别的残留副本移出插件扫描目录，安装并检查新文件后恢复商城；同版本也重新安装，失败时恢复原目录。小黄鸭 1.0 和 2.0 共用 `Decky LSFG-VK` 目录，MAKO 独立保留，初始化只在组合内处理 MAKO 一次。云端同步任务自身不运行客户端卸载或服务命令。

开发机验证：`tests/test_framegen_pipeline.py` 使用本地 ZIP、静态解析和模拟发布；`tests/test_framegen_updates.sh` 使用模拟下载与临时插件目录；`tests/test_lsfg_choice.sh` 检查选择、取消、清理顺序、停止/写入/启动失败恢复与 MAKO 保留。真实 SteamOS 安装只在目标掌机进行。汉化完整性强制要求见 `AGENTS.md`，不能以字典覆盖替代真实界面文案核对。

初始化和常用插件组合还会选择是否卸载机器上原有的全部插件，默认保留；选择卸载时先停止商城并把原插件移到扫描目录外，整组安装失败时恢复原插件。FreeDeck 在组合之后安装，避免被本次清理移除。`tests/test_plugin_cleanup_choice.sh` 验证两种选择、取消、范围和失败恢复。
