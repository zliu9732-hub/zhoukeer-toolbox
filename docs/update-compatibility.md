# 历史版本自动升级检查

发布包生成后必须通过 `tests/test_legacy_update_matrix.py`，不能仅检查下载成功、SHA256 或版本号。

测试枚举本地完整仓库中的 1.x、2.x、3.x 标签，按照 `update.sh`、`core/download_policy.sh`、`core/source_status.sh` 的 Git 对象分组。每组使用原版更新程序、原版依赖和该组最早版本的配置，执行启动自动更新，调用真实的新版本安装器。下载和系统身份使用模拟命令，禁止执行真实提权、包管理、服务、EFI 或网络操作。

检查完成安装后的版本、启动器、更新程序、插件安装模块及配置示例与发布包一致，并检查客户配置、已下载应用与已安装插件数据仍保留。检查设有 60 秒启动执行限时。缺少历史标签时直接失败，不能把“没有测试到历史版本”当成通过。

3.5.7 修复了配置示例缺少四项安装器仍要求读取的默认值，造成下载成功但安装失败的问题。3.5.8 为启动版本检测的每条备用地址保留时间，防止前面的失效地址及其重试耗尽整个检测窗口。手动更新的重试行为不变。

这些是命令模拟与真实安装文件的兼容性验证，不代表所有客户网络或掌机都已实测。旧版已经下载并运行修复后的安装包时即可通过原流程升级；若机器完全无法连接它原有的地址，发布端不能绕过网络故障执行代码。
